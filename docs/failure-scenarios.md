# Отказы и пограничные случаи

Примеры из таблицы воспроизводятся тестами на Roslyn. Запустите их командой
`dotnet test -c Release --no-build --filter 'Category!=Measurement'` после сборки решения.

| Ситуация | Результат |
| --- | --- |
| `var value = task.Result;` внутри `lock` | AG001 остаётся, вставка `await` нарушила бы правила языка |
| Наследник `Task<T>` объявляет собственный `GetAwaiter` | AG001 относится к унаследованному `Result`. Исправление недоступно, поскольку `await` может вызвать другой код |
| Есть `Send(long, CancellationToken = default)` и `Send(int, CancellationToken)`. Вызов `Send(1)` сделан из метода с токеном | AG003 появляется. Добавление токена переключило бы вызов на вторую перегрузку, поэтому исправление не предлагается |
| Необязательный параметр использует `CallerArgumentExpression` | AG003 остаётся без исправления, поскольку вставка аргумента может изменить строку, которую передаёт компилятор |
| `Capture(Send())` с `CallerArgumentExpression` во внешнем вызове | Без защиты строка `Send()` изменилась бы на `Send(token: ct)`. AG003 остаётся без исправления. Тест компилирует и исполняет оба варианта |
| Токен доступен в параметре лямбды | AG003 появляется. Исправление пропускается, так как вывод типов параметров лямбды может зависеть от окружающего вызова |
| Незакрытый вызов `Missing(value:` после `task.Result` | Ошибки синтаксиса сообщает компилятор. Корректно привязанный `Result` всё ещё даёт AG001, ошибки анализатора нет |

Если чистый потребитель сообщает `NU1101`, выполните `dotnet pack src/AsyncAnalyzer -c Release -o artifacts/feed`
из каталога проекта. Источник пакетов демо ограничен этой папкой.
