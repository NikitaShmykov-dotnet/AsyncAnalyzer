# 002. Проверка исправлений

AG001 меняет только прямой инициализатор локальной переменной с
`Task<T>.Result`, где статический тип получателя — сам `Task<T>`.
Так исключается скрытый awaiter наследника. Правка пропускается, если
она затронула бы комментарии или директивы внутри выражения. После
замены проверяем ошибки компилятора в изменённом файле. Это покрывает,
в частности, запрет `await` внутри `lock`.

AG003 добавляет именованный аргумент после существующих. Порядок уже
записанных выражений сохраняется. Roslyn повторно привязывает новый вызов
в исходной области видимости. Предлагаем изменение только при совпадении
символа, включая параметры типа у generic-методов. Внутри лямбд
AG003 оставляет предупреждение без исправления.

Оба исправления проверяют сам редактируемый вызов и цепочку окружающих
операций. Если вызов, конструктор или индексатор получает неявный
аргумент `CallerArgumentExpression`, правку пропускаем. Например,
`Capture(Send())` может передавать строку `Send()` во внешний вызов.
Проверка консервативна и пропускает правку даже при захвате соседнего
аргумента. Явно заданная строка исправление не блокирует.

Исправления проверяются по одному. В файле с ошибками компиляции
действия могут быть недоступны до устранения ошибок.
